# Old Phone OS Interface 0.2.0

The current OPOS interface is the Surface Duo operating system. That interface is not in this repository, and this release does not include a hardware dossier.

What is here is the Meta hackathon reference (October 2026, Indie developer track). It pauses less essential work on a simulated older phone so calls and messages can stay available until a time you choose. Optional Meta Muse Glimmer 30B, on your own computer, can explain those choices. It is not the phone's operating system. See [reference/meta-hackathon/README.md](../../reference/meta-hackathon/README.md).

The public demo of the reference is [opos-demo-production.up.railway.app](https://opos-demo-production.up.railway.app). It answers from battery rules, with Glimmer off. [Watch the demo video](https://youtu.be/ZiFa_5aUD_Y). Project story: [fortheloveof.studio/code/old-phone-os](https://fortheloveof.studio/code/old-phone-os/).

## Reference quickstart

Requires Python 3.11 or newer and a web browser. From a checkout of this repository:

```sh
PYTHONPATH=src python3 -m opos.web --port 8765
```

Open http://127.0.0.1:8765/?demo=1 and leave the terminal running. Ctrl-C stops it. Battery, calls, and messages are simulated. This does not start the Surface Duo OS.

Optional per-user install of the reference, still using this checkout:

```sh
sh install.sh --yes --no-launch
export PATH="$HOME/.local/bin:$PATH"
opos run --defaults
opos status
```

The Windows installer is still untested at runtime.

## postmarketOS reference

Package recipes and a QEMU development workflow are in [docs/pmos.md](../../docs/pmos.md). On November 3, 2026 an aarch64 postmarketOS image of this reference booted in QEMU to the lock screen, and Unlock reached Home. That image used the packaged software renderer. This 0.2.0 tree has not repeated that boot.

`sh packaging/pmos/qemu-smoke.sh` only prints a plan. `sh packaging/pmos/qemu-smoke.sh --guest` boots a tiny Linux initramfs in QEMU and looks for `OPOS_QEMU_GUEST_SMOKE_OK`. That guest is not postmarketOS and does not show OPOS.

Easy setup is documented in [docs/pmos-easy-setup.md](../../docs/pmos-easy-setup.md). `sh packaging/pmos/easy/easy-install.sh IMAGE` prints a plan and changes nothing. `easy-install.sh --flash IMAGE` checks the file header, asks you to type `reboot` (or pass `--yes`), then runs `pmbootstrap flasher flash_rootfs`. The image path is not passed to pmbootstrap. Physical-device flashing is untested. Do not flash a phone from these instructions.

The packaged kiosk still uses the same simulated battery and modem as the desktop demo.

## What 0.2.0 changes

- The hackathon interface is labeled as a reference in [reference/meta-hackathon/README.md](../../reference/meta-hackathon/README.md). It stays on its current paths so the package and tests keep working.
- Version 0.2.0 in the Python package, the About text, `opos --version`, and the `opos` postmarketOS package (`pkgver` 0.2.0, `pkgrel` 0). The UI package `postmarketos-ui-opos` stays at pkgver 1.
- Easy-setup wording matches the scripts. The old "reboot several times" warning was not something the scripts do, and it has been removed.
- CI runs ShellCheck on the easy-setup scripts, a dry run that proves plan mode makes no changes, and the tiny QEMU guest smoke.
- The reference quick start is the same command as 0.1.0.

## Proven

- Desktop reference server from this tree (`python3 -m opos.web`).
- Unit tests, including the easy-install plan-mode dry run.
- ShellCheck 0.11.0 on `packaging/pmos/easy/*.sh` and `packaging/pmos/qemu-smoke.sh`.
- QEMU x86_64 guest smoke printing `OPOS_QEMU_GUEST_SMOKE_OK`.

## Not proven

- The Surface Duo OS interface. It is not in this repository.
- Any physical phone.
- `easy-install.sh --flash` and `pmbootstrap flasher flash_rootfs` on hardware.
- A postmarketOS or reference-UI boot from this 0.2.0 tree. The November 3 QEMU UI boot was an earlier build.
- Real battery readings, real calls and texts, and on-phone model inference.
- The Windows runtime.
- Downloading `opos-runtime-source-20261109.tar.gz` from GitHub. That file is not attached until the release below is published. Until then, build packages with `OPOS_LOCAL_SOURCE=1` as [docs/pmos.md](../../docs/pmos.md) describes.

## Release owner steps

Do not run these until you approve the tag and the GitHub Release. They are not done in the release-candidate pull request. Delete this section before pasting the notes onto the website or into the GitHub Release body if you do not want the commands on the public page.

1. Merge the release-candidate pull request. Check that the `tests`, `easy-setup`, and `qemu-guest-smoke` jobs are green on the merge commit.
2. From a clean checkout of that merge commit (`MERGE_SHA` below):

```sh
git fetch origin
git checkout main
git pull origin main
git rev-parse HEAD
git tag -a v0.2.0 MERGE_SHA -m "Old Phone OS Interface 0.2.0"
git push origin v0.2.0
python3 packaging/pmos/make-runtime-source.py \
  --root . \
  --output opos-runtime-source-20261109.tar.gz \
  --archive-root old-phone-os-source
sha512sum opos-runtime-source-20261109.tar.gz
```

3. The sha512 must be exactly:

```text
4d29d714e2768f9940dbab1b0869f0d510fc6b8bdb7267602bae17f423fdcee515d810b51851c8b6baf9cd182312a72abfaa6d104070658d2f7966ff39b2e21c  opos-runtime-source-20261109.tar.gz
```

That is the digest in `packaging/pmos/opos/APKBUILD`. If it differs, do not upload the archive; the recipe would not match the file.

4. Create the GitHub Release and upload that archive as the asset name `opos-runtime-source-20261109.tar.gz` on tag `v0.2.0`. The recipe URL is `https://github.com/louiscalata/old-phone-os/releases/download/v0.2.0/opos-runtime-source-20261109.tar.gz`.
