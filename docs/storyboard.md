# Demo scene plan

This is a proposed sequence, not a completed video or a performance measurement. Keep the final video below the event's stated length limit and show only evidence tied to its actual source/configuration.

| Scene | What to show | Scope to state |
|---|---|---|
| Home and current settings | Actual OPOS navigation and saved choices | Identify desktop simulation or postmarketOS QEMU. Do not imply a physical phone. |
| Low-battery policy | An explicitly seeded simulator or the actual QEMU policy state | Rules keep essentials allowed and may defer other tasks; this is not measured battery life. |
| Plan or Ask | The actual request and complete visible result | A fixed-order Plan or critical-battery rest is rules behavior, not a model answer. Keep errors and waits visible. |
| Meta runtime evidence | A genuine compatible-server response, if captured, or a clearly labeled historical receipt | Do not animate stills into fake typing/loading or claim desktop evidence was a native answer. |
| Native kiosk | Actual Lock/Home frames for the accepted image | Disclose that the packaged hook sets WLR_RENDERER=pixman after default GLES2/GBM failure (November 3 QEMU image); a virtual machine, not a phone. |
| Credits and limits | GPL source, mixed development contributions, validation scope | No all-Meta authorship, physical-call or native-inference claim without proof. |

Stills and sampled frame sequences must be labeled as such. Preserve real elapsed timing for recorded requests and mark explicit cuts between separate takes. Historical GIFs in the README are earlier simulations; the wait GIF uses a stand-in server and simulated answer.

Meta runtime routing is separate from development authorship. See [../NEW-WORK.md](../NEW-WORK.md), [../WORK-BY-MODEL.md](../WORK-BY-MODEL.md) and [provenance.md](provenance.md). No publication or device-changing operation is authorized by this plan.
