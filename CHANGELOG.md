# Changelog

Notable changes to Old Phone OS Interface (OPOS), in Keep a Changelog style.

## Unreleased

### Added

- Native GTK 4 shell for the Surface Duo image (`src/opos/native/`, launcher `packaging/duo-os/opos-native`): one window across both screens, where every frame is a complete snapshot of what the server last said and a tap is answered in one frame. `opos-kiosk` hands its process to the launcher unless `/etc/opos/native-off` exists, and the launcher hands it back to the browser kiosk when GTK cannot load, first-run setup is not done, the PIN lock is on, the owner chooses the old interface or the shell keeps ending. Clock, Contacts, Notes and Call log appear only when `OPOS_APPS` names them. When the lid closes the shell locks and both panels go dark; they are lit again at their saved brightness when it opens, and also on start, when the lid signal is lost, on any handled end and before the browser starts. Not run on the phone (**NOT_RUN**) (#130).
- Network (Wi-Fi) screen for the native shell, opened from a Network button in Settings, on the server's existing `net_status`, `net_scan`, `net_join`, `net_forget` and `net_wifi` actions: scan, join with a typed password (or none for a saved or open network), join a hidden network, forget, disconnect and turn Wi-Fi on or off. Forget, Disconnect and Turn Wi-Fi off take two taps, and Wi-Fi is never switched while its state is unknown (#132). Audit fixes: a hidden network's password belongs to the name it was typed for and is emptied when that name is edited, the radios reads and the lists share one order, and the confirming Disconnect tap reads the radios again and disconnects only when that read still names the prompt's network (#136). This build was not run on the phone (**NOT_RUN**); the owner's November 13 check was of the PC session's earlier patch 0013.
- `docs/duo-device-checks.md`: a runbook with one check, C01 to C32, for each phone check the docs still mark NOT_RUN, and `tests/test_duo_device_checks.py`, which fails when a NOT_RUN statement in `packaging/duo-os/NATIVE.md`, `ROADMAP.md`, `docs/duo-os-final.md` or `docs/duo-usb-install.md` has no check quoting it. Nothing in it has been run (#145).
- Unit converter at `/convert` for length, mass, volume and temperature with fixed decimal factors, on only when `OPOS_APPS` names `convert`; the Duo drop-in now names `clock,contacts,notes,calc,calls,convert`. With the PIN lock on and the phone locked, a read gives the locked body and a conversion is refused. `tests/test_apps_gate.py` checks that every app route answers 404 until `OPOS_APPS` names that app, that each app answers alone, that the whole set adds one `/apps-home.js` tag, and that the home page with the lock and the six Duo apps (101,998 bytes) stays within the 102,000-byte gate. `tests/test_duo_push.py` runs `push-to-duo.sh` with stdin closed and a 60 s timeout. Tested on the Mac only; every on-device check is **NOT_RUN** (#146).
- Native Converter works each conversion out in the shell's own process with the server's converter code (`opos.convert` and the `/convert` page's handler), so it needs no server and shows the same answers and refusal words as `/api/convert`; it asks the server only if that code cannot be loaded. `OPOS_APPS` still decides whether the screen exists. Tested against a stand-in toolkit only; not run under real GTK or on the phone (**NOT_RUN**).
- Duo `opos-powerkey`: short power presses toggle both panels through `bl_power`, with shared startup unblanking, repeat/long-hold filtering and debounce; not run on a phone (NOT_RUN), and touch while blanked is not known.
- Duo native shell: the hinge angle and back mode (`src/opos/native/hinge.py`, `facing.py`, `posture.py`, `layout.py`; [NATIVE.md](packaging/duo-os/NATIVE.md#the-hinge-and-back-mode)). `hinge.py` is a read-only D-Bus client of sensorfw (`hingesensor` and `accelerometersensor`) that also connects to sensorfw's data socket, without which sensorfw drops the session after about 10 s and the angle freezes; it never starts the service. The posture is closed (from the lid switch only), book, flat, tent or back, with 6 degrees of hysteresis, and each change is one log line. Folded back with the lid open, only the screen that faces you is lit and the layout is one screen wide (accelerometer z above +0.35 g: the right screen, below -0.35 g: the left, otherwise the screen touched last; a verdict must hold 0.8 s), and touches that go down on the dark screen are ignored. Polling is adaptive (every 0.25 s while the hinge moves or at 300 degrees or more, otherwise every 1 s, the accelerometer every 2 s), and neither sensor is read while the lid is closed. Settings > Hinge shows the posture and the angle, and in back mode that one screen is lit and the other dark. Tested against fakes. As reported by the PC session, seen on one phone in one session as an installed release: all five postures in the shell's log, the back-mode layout, taps, the flip-over switch and both screens lit after the lid opens. Idle CPU of the shell and the sensor service, peer-measured, clock ticks per 30 s: 93 and 45 with fixed polling, 31 and 21 adaptive, 20 and 0 with the lid closed. A dark screen ignoring touch, the Settings Hinge line on the glass, a cold boot with the delayed sensor start and ten cold boots are **NOT_RUN**.
- Duo image: `opos-sensorfwd-delayed.timer` starts `sensorfwd.service` once, 120 s after boot, unless `/etc/opos/sensors-off` exists (the file blocks future starts only; a live stop is `sudo systemctl disable --now opos-sensorfwd-delayed.timer`, then `sudo systemctl stop sensorfwd`); stage 1 only, `sensorfwd.service` stays disabled. A cold boot with the timer and ten cold boots are **NOT_RUN**.
- Inference page (`/monitor`, behind `OPOS_MONITOR=1`; `src/opos/monitor.py`, `src/opos/monitor_web.py`, `src/opos/web_static/monitor*`): a read-only page that says whether a model server answers on the phone's own loopback, shows the battery percent, health (only when the battery's own gauge reports it, never an estimated, assumed or typed-in value) and source, and optionally shows an AGIW Inference Monitor on a computer you own (`OPOS_AGIW_URL`, `OPOS_AGIW_HOST`; nothing leaves the phone unless `OPOS_AGIW_URL` is set). The page's check of the phone's own model server follows `OPOS_LOCAL_URL` only if you already set it for the Helper, and setting it changes the Helper too. Settings gets a link to it when the switch is on, added at serve time so the main page does not grow; `/api/monitor` needs the session token, is rate limited, and asks the monitor outside the request lock. The Duo OS image's `opos-server.service` turns it on and reads an optional `/etc/opos/monitor.env` (only a commented example ships); the privacy notice now names the Inference page among the opt-ins. Tested against fakes and loopback servers only; not seen on the phone. On the hardened units only loopback egress works, so a reverse tunnel is the way there (`packaging/duo-os/README.md`).
- Measured drain for a live battery (`--live-battery`): time left, the goal check, the reserve and the helper's hours left follow an exponentially weighted discharge rate taken from the phone's own level changes (and its charge counter when readable) instead of the simulated drain model, which stays the figure until 10 minutes of discharge have been observed. The state payload gains `battery.drain` (basis, rate, sample age, observation window). Tested on synthetic discharge traces only; not yet measured on the phone.
- `OPOS_SPAN` / `--span PANE,HINGE` (`src/opos/span.py`): for a browser window that covers both panels of a two-screen phone, the server serves the page as if the browser had reported two viewport segments, so the existing Foldable layout keeps content off the hinge. Chromium on Linux cannot report segments, so the Surface Duo OPOS OS image's server can be told where the hinge is: 675,42 from the port's 2784 x 1800 output at phoc scale 2, set in `opos-server.service` after it was checked in headless Chromium at 1392 x 900. Not yet measured on the phone. Unset, the page is unchanged.
- `OPOS_PANES=1` (`src/opos/panes.py`, `docs/jaryo-panes.md`): on the window that spans both panels the thumb pane is black with light text and the list pane white with dark text (pressed, active and on controls stay the inverted fill of their own pane), and a Hand setting in Settings > Display (Right or Left) decides which physical pane is which and mirrors the layout. Served as separate `/panes.css` and `/panes.js` like the on-screen keyboard; `web.page()` does not change and, unset, the panes assets and tags are absent. The Network, first-run and time zone pages follow the Jaryo text-button rules (two colors, square corners, dashed unavailable buttons, 48 px targets, a drawn checkbox) with the flag on or off. Checked in headless Chromium at 1392 x 900, not yet on the phone.
- Surface Duo with OPOS as the only interface (`packaging/duo-os`): a build script, offline checks and boot-evidence tools for an image on the community Droidian port's rootfs, where `opos-server.service` runs the OPOS server on the phone's real battery and `opos-session` starts phoc (hwcomposer, no shell mode) with a full-screen Chromium kiosk. Ran on the owner's Surface Duo 1 on November 7, 2026, RAM-booted from a PC; the owner confirmed it worked and logs showed phoc on hwcomposer and the real battery from sysfs. It was seen on one phone in one session; no speed, battery-life or stability measurements; calls and texts are still simulated; RAM-boot only.
- `deploy/duo-opos-boot.ps1`: the install chain for that image from a Windows PC (misc brake, userdata format, TWRP, hash-verified push, one RAM-boot of the kernel), with the phone found by probing TCP 22 across the /24 of the USB network adapter instead of waiting for a gateway, an optional ssh key for diagnostics, no hard-coded paths and a dry run unless `-Yes`. Tests parse it, read its safety rules and run its probe against loopback; it has not been run in this form.
- Surface Duo on stock Android: `--live-battery` (`LiveBattery`), `deploy/duo-termux.ps1` and `deploy/termux-setup.sh`; one session on the owner's phone on November 7, 2026 (see `docs/duo-android.md`).
- Over-the-air updates for the Surface Duo OS image ([design and as-built notes](docs/ota-update.md)): a root updater with its systemd units, installed by `packaging/duo-os/build-image.sh` (`OPOS_UPDATE_SIGNERS`, `OPOS_UPDATE_URL`); an opt-in update client and `/update` page in OPOS; `tools/opos-release.py` and `deploy/duo-push-update.ps1` to build, sign and push a release ([how-to](docs/ota-release-howto.md)). Settings, About has an Updates link to the page. Review fixes: the update service has no start limit that a writer of the inbox could trip; the smoke test uses a port the kernel picks; a rollback requested through the inbox is limited to one step back per applied update and does not burn the serial. Implemented and tested on Linux with stand-ins for systemd, runuser and the browser; not tested on the phone.
- VoLTE (`docs/duo-volte.md`): whether `ofono-binder-plugin-ext-qti` can be installed, and whether IMS registers, are open checks. **NOT_RUN.**

### Changed

- Dark theme ink is now pure `#fff` on `#000` (was the softer `#e6e2d9`), so the AMOLED screen's black pixels stay off and the contrast is 21:1. The light theme keeps its soft e-ink paper pair, `#1a1a1a` on `#f3f0e8`. Applies to the kiosk pages, first-run and setup pages, the on-screen keyboard, the native shell and the panes. Page bytes are 6 bytes shorter per colour use and the recorded page digests are re-recorded. Not seen on the phone (**NOT_RUN**).
- Alarms: an alarm or timer ring plays `src/opos/sounds/alarm.wav` through `paplay`, started without a shell: six beeps of 0.4 seconds from 20 to 70 percent of the paplay stream, and a beep that has not ended after 2 seconds is terminated, then killed, so one ring ends within 24 seconds. Stop, Snooze, Delete and switching an alarm off end the ring. The sink volume is not changed, no media role is set, and no package, service or privilege is added; the image recipes do not add `paplay`, and when it is missing the alarm shows on screen only. Whether the tone is heard on the phone is **NOT_RUN**; vibration stays off (#144).
- PIN lock (`OPOS_LOCK=1`): while the phone is locked, every app read (`/api/contacts`, `/api/notes`, `/api/clock`, `/api/calls`) and every write that stays allowed answers with the locked `/api/state` body instead of names, numbers, note titles, alarm labels and call rows; the Clock answer adds only whether an alarm is ringing and its time. The home page loads `/pin.js`, a digit pad: showing the lock screen locks the server, and the lock screen comes off only after the server has answered that the phone is unlocked. The lock screen's missed-call count is read from the call log (#139). A Lock request that was lost or answered 429 no longer lets Unlock skip the PIN, a 429 to the digits is reported as busy rather than as a wrong PIN, the pad fits narrow screens, and the wrong-PIN wait stops at 8 hours from the 15th wrong try on, with no wipe (#142). Nothing changes with `OPOS_LOCK` unset, and `page()` does not change. The pad was run in node against a stand-in page; a browser and the phone are **NOT_RUN**.
- Native shell: `OPOS_SERVER_URL`, accepted only as `http://127.0.0.1:PORT`, replaces its use of the Helper's `OPOS_LOCAL_URL`; its requests use no proxy and follow no redirect to another address. A state is drawn only with the server's answer about its PIN lock, and no answer holds the shell on its lock page (5 in a row: the browser takes over). Phone says when the answer to a call or a hang-up is missing. A lost lid watcher is looked for again 5 s, 15 s and 30 s later, then every 60 s. Anyone who set `OPOS_LOCAL_URL` to point the shell at another OPOS server port must now set `OPOS_SERVER_URL`; the image sets neither. Checked with a stand-in toolkit only; **NOT_RUN** on the phone (#138).
- Native shell lid blanking: with no saved brightness file, a panel whose `brightness` file is there but cannot be read is written its default (capped by its readable `max_brightness`) and stays listed as failed until a read shows it lit; an absent `brightness` file is never created. A `PowerSaveMode` of 1 to 3 that the shell refuses (the lid reads open) reads 0, the mode in force. Not run on a Duo (**NOT_RUN**) (#135).
- `deploy/duo-rootfs-install.sh`: rehashes all three images directly before the userdata erase and refuses with nothing erased if one changed; RAM-boots private read-only copies of the TWRP and boot images made when they are checked; rehashes the rootfs image before the push; requires the same product again after the return to the bootloader; refuses before the erase unless `fastboot getvar unlocked` answers `unlocked: yes`. The battery stays a manual step. Tested with stand-ins for fastboot and adb only; a run on the phone is **NOT_RUN** (#137).
- Record the reported November 12 Duo G0–G3 results, G2b owner acceptance, Magisk-patched boot_a backup and measured TWRP round trip back to installed OPOS with one kernel RAM-boot and no reinstall; G3's identical bytes cannot show a silently ignored write and its dd timing proves nothing. G3b, G4 and later remain **NOT_RUN**. Default the persist probe to head (dd remains selectable), omit unsupported sgdisk info reads, and document the RAM-booted kernel's debugfs trap.
- Duo dev and release images disable Wi-Fi protected management frames with `90-opos-wifi-compat.conf` (`wifi-sec.pmf=1`) for driver compatibility; management frames are unprotected. The November 12 phone A/B evidence covers one access point and one run per variant, with a further reported pmf-only join on a fresh install and automatic reconnect after a reboot on the same access point (not a freshly built image); the freshly built image phone check remains **NOT_RUN**.
- Duo image hardening: release base pinning and previous-OPOS refusal, private staging and exclusive verified publication, release/dev marking, owner SSH recovery or explicit no SSH, `OPOS_DEV_SPAN`/`OPOS_DEV_SUDO` opt-ins, removal of the root telnet shell on the USB link and USB-subnet password login, `OPOS_NET_POLKIT` checks and corrected backlight diagnostics; offline fixture tests only, phone checks remain **NOT_RUN**.
- The status bar and the call, from the interface plan (`src/opos/statusbar.py`): a clock that is not set (state `clock` `--:--`, or a browser year before 2026) is drawn as `--:--` and "Time not set" on the status bar, the lock screen and the Home dateline; the status bar says "In call", else a state note ("Simulated battery", "Battery not readable", "Clock not set"), else "Offline"; low battery reads `LOW 12%` (the Shade title `12% LOW`) with the double border; the bar says "Helper on" instead of naming a model, and Settings > About no longer repeats it; a call is a boxed bold notice with an inverted Hang up, Home's card says who is on the line, and the lock line shows the newest notice instead of "New notice". The Shade's Recent notices use the same clock rule; on a narrow bar the note gives way (an ellipsis) before the chip or "Helper on"; `tests/test_uxp30_budget.py` also holds the home page the server sends with every switch on (built the way `web.main()` builds it) to the interface plan's 102,000-byte wave gate.
- Documentation for the Surface Duo runs: `README.md` Limits, `ROADMAP.md` and the documentation index now separate what ran on the phone (one phone, one day) from what is simulated or unmeasured, and the Droidian USB notes are labelled historical.
- `opos-kiosk` waits for the OPOS server before every start of the browser, so the browser comes back only after a restarted server answers.
- The Duo's `opos-server.service` keeps the page token in `/var/lib/opos/token` (`StateDirectory=opos`, `--token-file %S/opos/token`): `opos.web --token-file` now creates a missing file with mode 0600 (`src/opos/tokenfile.py`) instead of exiting, so a restart of the server, by systemd, an update or Restart helper, no longer strands the open page with a stale token. If the file cannot be made (a full disk, a read-only directory) the server still starts, keeps a token for that run only and says so on stderr; a file that exists but cannot be read or holds a bad token still stops it with status 2.
- The page heals itself when the server goes away or restarts: a poll that gets no answer within 8 s counts as a miss, two misses show a boxed banner under the status bar ("Not updating. Values shown may be old. Tap Reload."), a "?" before the battery figure and the Reload button at the bottom right, and one good answer clears them. Reload now reloads only if the server answers, so it can no longer leave a keyboard-less phone on a browser error page. A 403 after a restart (a new token) reloads the page once, at most every 10 s, instead of showing "This page is out of date" for ever, and "Restart helper" waits for the server instead of reloading after a fixed 6 s.
- Taps and focus survive the poll: the contacts, the threads, the open thread, the helper box (with its Why? button), the feature rows and the event list are rebuilt only when their content changed (`sync` in `js-4.js`), so a button that is pressed while a poll arrives still gets its click and a focused contact keeps the focus instead of dropping to the page after one poll. A poll whose state is what was last drawn now draws nothing at all (the memory figures and anything the page itself changed in between are accounted for), and the two 15 s clock timers write only a changed text: an idle Home or lock screen goes from about 58 DOM writes per poll and 24 layouts a minute to under 2 and about 4.
- README now includes an illustrative older-phone vignette, new final-tree Muse Glimmer Ask and Why? captures in light and dark, with all eight measured UI response times, the quoted first dark Ask answer, and current pause status. All eight requests returned Glimmer replies within the 115-second deadline; the new Why? measurements replace the earlier rules-fallback observations for this source. Simulation wording distinguishes the profile drain runs from the worn-battery burst-shaping evaluation; postmarketOS wording separates the recorded QEMU boot from outstanding integration acceptance and untested physical-phone behavior.
- `packaging/duo-os/NATIVE.md` no longer says that no hinge angle reaches Linux on the Duo: the kernel gives none, and the angle comes from sensorfw's hinge sensor. "The lid" and the `posture.py` row now say so, and new rows name `hinge.py` and `facing.py`.

## 0.1.0 - 2026-11-03

### Added

- Public snapshot (`bb9c846`): a prototype phone interface that keeps calls and messages on while pausing less essential work toward an owner's chosen time.
- A desktop demo with simulated battery, calls and messages, requiring Python 3.11 or newer; an optional local helper explains decisions and may add pauses.
- Follow-up (`857e235`): tests compare published simulation numbers with simulator results.
- Panel fixes (`bd0e465`): `pyproject.toml` and CI for Python 3.11 and 3.13.

### Changed

- Follow-up: renamed the displayed project name to Old Phone OS Interface; existing installer markers, service descriptions and package fields retain the old name.
- Panel fixes: clarified the simulated battery and modem in the postmarketOS kiosk, battery trade-offs and the meaning of a worn battery in the docs.

### Fixed

- Follow-up: handled incomplete helper replies, transport errors and deeply nested replies; limited claimed pauses to paused tasks and gave the last route the remaining time.
- Follow-up: made Wikipedia search ignore proxies and redirects.
- Follow-up: corrected demo-goal handling and wording, including empty batteries and goals set after their time.
- Follow-up: added one plain message for Python versions older than 3.11 on every platform.
- Panel fixes: used one final pause decision across screens, helper facts and simulated drain, with safety limits applied after owner actions.
- Panel fixes: shared the daily-goal budget across tasks in a fixed order and aligned simulated drain with the time-left estimate.
- Panel fixes: checked helper routes before sending Why and Ask questions, restricted the network route to private addresses and preserved route settings in installed services.
- Panel fixes: verified the optional AI-tools installer against a pinned SHA-256 digest and refused redirects to another host.
